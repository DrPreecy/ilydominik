# CWS clean-room design — Claude department (Opus, blind: read only starttoughts.md + docs/spec.md)

**Thesis.** CWS is a ledger plus a review queue. AI writes into the queue; a human signs entries into the ledger. Everything else is a view.

1. **Data model.** Typed events with ULID, author key id, hybrid logical clock and `parents[]` (hash-linked DAG). State = `fold(topo_sort(events))`. One JSONL file per device (`.cws/log/<device>.jsonl`), so merges never conflict textually; SQLite only as a disposable cache. An append-only set of immutable events is already a grow-only set — no CRDT library; semantic conflicts become warnings the human resolves. Markdown views (`STATE.md`, `DECISIONS.md`) are generated, never edited.
   *Trade-off:* no real deletion (forces §5); schema changes need upcasters.
2. **Authority.** Every authoritative event carries a WebAuthn/passkey signature (Windows Hello / Touch ID / phone) over the event hash; key in TPM/secure enclave, user-presence gesture required. The reducer decides authority by verifying signatures against pinned public keys outside the project folder — never by an `actor` field; unsigned = AI. One gesture signs the Merkle root of exactly the batch shown.
   *Guarantees:* a human event was approved by a physical gesture on an enrolled device over that exact content; forged/imported/cloud-injected "human" events fail. *Does not guarantee:* understanding; protection against truncation/rollback without a witness (cloud stores latest signed head + count); a compromised OS. A typed challenge code is not security (an agent reading the terminal can read it) — without a passkey, authority is labelled "unverified".
3. **Agents.** `cws context <purpose>` and one MCP server return a deterministic, size-bounded pack. Agents can call exactly one schema-validated tool, `propose(items[])`; output is AI-authored notes/claims/proposals with `derivedFrom`. Injection defence is structural (worst case: proposals a human must sign); delimiters are hygiene only.
4. **Command safety.** CWS does not run arbitrary agent commands; agents use their own harness permissions. Experiments run in an ephemeral container/VM with no secrets mounted, default-deny network with a signed allowlist, CPU/time/output limits, argv only. A regex denylist survives only as a UX warning, never as a guarantee. Without isolation, CWS refuses to run experiments.
5. **Secrets.** The event writer is the single choke point: gitleaks rules + entropy scan **before** append; a hit rejects the write and offers to store the value in the OS keychain with a `secret://name` reference. Render-time redaction is a second layer. Free-text bodies encrypted per item → crypto-shredding removes a leak everywhere without breaking the chain.
6. **Cloud.** Firestore `users/{uid}/projects/{pid}/events/{id}`: owner create only, never update/delete; one `head` doc as rollback witness. Clients re-verify signatures and recompute state; never trust a server-side state doc. Dashboard is static and read-only in v1.
7. **UX.** Three human actions: open (vision, phase, 3 next-step blocks) → tap a block (prompt + context handed to the chosen agent) → review colour-coded cards, swipe keep/drop, one fingerprint for the batch. Risks are a yellow banner with "continue anyway, because…".
8. **Not built.** Own chat UI / LLM client / agent runtime; regex guard or challenge codes presented as security; CRDT co-editing, multi-user; task hierarchies and dependency graphs before the core loop is proven; shell execution; tool paths from repo config; four per-tool wrapper file sets (one MCP server instead); own sandbox; dashboard writes; code generation.
